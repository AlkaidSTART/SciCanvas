# M4｜实验微调与错误恢复 MVP

**用户价值：**在当前实验基础上通过追问做小步修改；生成逻辑出错时系统能尝试自愈，同时保护可用版本。

**阶段状态：**已完成（2026-11-25）  
**依赖：**M3  
**PRD 来源：**F2 增量微调与快捷灵感标签、F3 运行时错误自动捕获与 Auto-Heal。

## MVP 边界

在 M3 单次生成的基础上增加带上下文的增量修改和最多两次自动修复。保留最后一个可用版本；AI 修复不是安全边界，所有重生成结果仍须经过 Schema 校验并在隔离运行时执行。

## 交付任务

- [x] **M4.1 当前实验上下文传递**：将当前 Schema、必要的参数/代码上下文和用户指令提交给模型；避免发送无关历史数据。
- [x] **M4.2 增量更新应用策略**：将模型返回结果校验后作为新版本预览/应用；失败时不替换当前实验。
- [x] **M4.3 快捷灵感标签**：提供至少三个可用快捷操作，例如加入随机噪声、对比基准模型、高亮梯度向量。
- [x] **M4.4 错误分类与捕获**：识别初始化、首帧绘制和运行阶段错误；采集最小必要诊断信息用于修复请求。
- [x] **M4.5 自动修复重试**：将错误反馈给模型并重载修正结果，最多重试两次；显示修复中与最终结果。
- [x] **M4.6 版本保护与恢复**：维护当前可用实验快照；重试失败后可继续操作旧版本并可显式恢复/重试。
- [x] **M4.7 修复流程测试**：覆盖一次成功修复、两次失败、无效 Schema、请求失败及原版本保留。

## 验收标准

- [x] 用户可在当前实验上提交追问并应用有效的增量修改。
- [x] 模型失败或输出校验失败时，当前实验不被覆盖。
- [x] 运行时自动修复最多两次，状态和失败原因清晰可见。
- [x] 修复成功后新实验可运行；修复失败后旧实验仍可继续交互。
- [x] 错误回传仅包含修复所需的信息，不包含服务端秘密或无关敏感数据。
- [x] 上述路径有自动化/可重复测试，lint/build 通过。

## 完成定义

用户可完成“生成 → 追问修改 → 出错时自动尝试修复 → 保留可用版本”的闭环。

**行为说明**

- 微调只发送 `currentSpec`、`currentParams`（最多 12 个原始值）与本次指令；修复只发送 `currentSpec` 与 `diagnostic`（阶段、截断到 500 字的错误信息、第几次尝试）。服务端再次校验 Schema、参数与诊断后才转发，且不读取上游响应体或回传凭证。
- 沙盒把首帧绘制错误标记为 `first-frame`，推演/后续绘制归为 `runtime`；自动修复最多两次，状态在画布底部依次显示“请求中 → 已应用验证中 → 成功/失败”。
- 每次首帧成功都会记录 `lastGoodAi` 快照。修复失败时自动恢复该快照（若无快照则回到默认预期实验），画布保持可交互；失败条同时提供“再试一次”（重新应用最后候选并再次触发修复）、“恢复上一版本”与“关闭”。
- 用户切回预设或关闭工作台时会终止进行中的修复，不再覆盖当前实验。

**验证结果（2026-11-25）**

- 单元/集成测试：`pnpm test` 共 11 个测试文件、117 个用例全部通过。新增覆盖：
  - 修复循环：一次成功、第二次成功、两次失败、请求失败、无效 Schema、取消、原版本不被修改；
  - 会话总线：成功、错误、超时、新等待替换旧等待；
  - 服务端：微调/修复上下文校验、参数与诊断边界、未知 mode、凭证与响应脱敏；
  - 客户端：微调/修复请求体、空指令拦截、修复结果二次校验；
  - 状态仓库：版本快照、恢复、切换清理、修复状态流转与失败重试。
- 构建与静态检查：`pnpm lint`（0 warning / 0 error）、`pnpm build` 通过。
- 浏览器端到端实测（本地 mock OpenAI 兼容服务）：
  1. 生成 AI 实验后使用“加入随机噪声”快捷标签完成一次有效增量修改；
  2. 构造初始化失败的微调结果，观察第 1 次修复候选仍失败、第 2 次修复成功，画布底部显示“自动修复完成 2/2”且新版本可运行；
  3. 再构造首帧绘制失败的微调结果，两次修复均失败后显示“自动修复失败”，自动恢复上一可用版本，失败条“再试一次 / 恢复上一版本 / 关闭”可用，关闭后沙盒仍保持运行。
- 依赖真实模型凭证的联调未在本环境执行；配置 `.env` 后可按上述步骤用真实模型复现。
