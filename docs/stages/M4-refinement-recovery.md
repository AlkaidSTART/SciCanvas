# M4｜实验微调与错误恢复 MVP

**用户价值：**在当前实验基础上通过追问做小步修改；生成逻辑出错时系统能尝试自愈，同时保护可用版本。

**阶段状态：**待开始  
**依赖：**M3  
**PRD 来源：**F2 增量微调与快捷灵感标签、F3 运行时错误自动捕获与 Auto-Heal。

## MVP 边界

在 M3 单次生成的基础上增加带上下文的增量修改和最多两次自动修复。保留最后一个可用版本；AI 修复不是安全边界，所有重生成结果仍须经过 Schema 校验并在隔离运行时执行。

## 交付任务

- [ ] **M4.1 当前实验上下文传递**：将当前 Schema、必要的参数/代码上下文和用户指令提交给模型；避免发送无关历史数据。
- [ ] **M4.2 增量更新应用策略**：将模型返回结果校验后作为新版本预览/应用；失败时不替换当前实验。
- [ ] **M4.3 快捷灵感标签**：提供至少三个可用快捷操作，例如加入随机噪声、对比基准模型、高亮梯度向量。
- [ ] **M4.4 错误分类与捕获**：识别初始化、首帧绘制和运行阶段错误；采集最小必要诊断信息用于修复请求。
- [ ] **M4.5 自动修复重试**：将错误反馈给模型并重载修正结果，最多重试两次；显示修复中与最终结果。
- [ ] **M4.6 版本保护与恢复**：维护当前可用实验快照；重试失败后可继续操作旧版本并可显式恢复/重试。
- [ ] **M4.7 修复流程测试**：覆盖一次成功修复、两次失败、无效 Schema、请求失败及原版本保留。

## 验收标准

- [ ] 用户可在当前实验上提交追问并应用有效的增量修改。
- [ ] 模型失败或输出校验失败时，当前实验不被覆盖。
- [ ] 运行时自动修复最多两次，状态和失败原因清晰可见。
- [ ] 修复成功后新实验可运行；修复失败后旧实验仍可继续交互。
- [ ] 错误回传仅包含修复所需的信息，不包含服务端秘密或无关敏感数据。
- [ ] 上述路径有自动化/可重复测试，lint/build 通过。

## 完成定义

用户可完成“生成 → 追问修改 → 出错时自动尝试修复 → 保留可用版本”的闭环。

## 暂不纳入

论文截图识别（M8）、遥测探针（M5）、实验跨会话持久化（M7）。
